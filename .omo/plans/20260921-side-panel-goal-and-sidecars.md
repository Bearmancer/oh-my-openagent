# Side panel: goal, sidecars and the state omo grew since beta.53

The panel shipped against `v5.0.0-beta.53`. omo is now `beta.80` — 872 commits and 22 releases
later — and it grew three subsystems the column is blind to, plus new child states that make the
current AGENTS rows actively wrong. This plan lands that in staged increments, each one a complete
shippable change with its own tests, evidence and commit.

## Increments, in order

| # | Increment | Why first / why later |
|---|---|---|
| 1 | **GOAL section** | Documented surface, no rebase needed, biggest visible gap |
| 2 | Rebase the branch onto current `dev` | Increments 3-5 read source that does not exist in this checkout |
| 3 | Kibitzer section | Resident sidecar that spends money invisibly |
| 4 | Parked reflection row | Upstream already added a lock-free reader for it |
| 5 | Child accuracy + category vocabulary | Daemon / workpool states; `deep` → `deep-low`/`deep-high` |
| 6 | `sections.memory` | The schema switch has had no implementation since the first PR; 3 and 4 give it content |

Only increment 1 is decision-complete below. Increments 3-6 depend on source that arrives with the
rebase, so their details are re-derived after increment 2 rather than guessed now.

## Increment 1 — the GOAL section

### What the host gives us (verified, not assumed)

`ExtensionContext` carries the path directly:

```ts
/** Absolute goal-store path for this session; reading it does not create the file. */
readonly goalStoreFile?: string
```

That is the same object `panelFactsFrom` already reads for `model` / `sessionManager`, so no new
host coupling is introduced — one more optional field off an object we already hold.

The file is written by `senpi`'s goal store as:

```js
`${JSON.stringify({ version: STORE_VERSION, goal }, null, 2)}\n`   // atomic write
```

and the record is richer than the `create_goal` tool result shows:

```js
{ id, threadId, objective, status, tokensUsed, timeUsedSeconds,
  consecutiveContinuations, unattendedContinuations,
  createdAt, updatedAt, lastStartedAt, tokenBudget? }
```

`consecutiveContinuations` and `unattendedContinuations` are the continuation state worth showing:
they say the goal loop kept going on its own, and how far.

### Two constraints recon settled

1. **No subscribable goal event.** `goal_store_changed` exists on senpi's internal bus but is NOT in
   the extension event union, so `pi.on` cannot take it. Refresh therefore rides the panel's
   existing refresh path (`turn_end` / `agent_settled` / `message_end` / `tool_execution_start`),
   exactly like the usage-poller nudge. To keep that free, the reader **stats the file first and
   re-parses only when mtime or size changed**.
2. **The file can be caught half-written.** Upstream's own loader carries a recovery branch for a
   corrupt parse, which means partial reads are real. Our reader validates on read and answers
   `undefined` rather than throwing — a panel with one missing section beats a panel that dies
   mid-frame, the rule the component already follows everywhere else.

### Rows

```
GOAL  active · 2h14
objective  Extend the side panel with the subsystems omo gained…
spend      148K · 2h14
budget     ███████▌░░░░░░░░ 47%          (only when tokenBudget is set)
loops      6 continuations · 4 unattended (only when non-zero)
```

- The heading carries status and elapsed, so a folded read still answers "is it running and how
  long".
- `objective` is truncated to the column; the **whole** text opens in the shared viewer on click,
  which is why the row gets an action — objectives run to kilobytes.
- `loops` appears only when the goal has actually continued on its own. Zero is not news.
- `budget` appears only when `tokenBudget` is set, and reuses `format/bars.ts` with the same
  pace-marker treatment the usage bars use.
- A `complete` / `blocked` goal still renders, with the status carrying the colour (blocked ⇒
  `warning`): the panel should not go silent the moment the run ends.

### Failing-first proof, per behaviour

Every one captured RED before the production change, `#given … #when … #then`, colocated, Bun.

**`data/goal.test.ts`**
- a valid store file → the facts a row needs
- absent file → `undefined`, and **no throw** (the common case: most sessions have no goal)
- half-written file (truncated JSON) → `undefined`, not a crash — the case upstream's own recovery
  branch proves is real
- a record whose `status` is not one senpi writes → ignored rather than printed raw
- unchanged mtime → the file is **not** re-parsed (guards the per-refresh cost)
- changed mtime → re-parsed

**`sections/goal.ts`**
- active goal → heading with status and elapsed
- `tokenBudget` set → a bar; absent → no budget row
- `unattendedContinuations > 0` → the loops row; both zero → no row
- `blocked` → warning colour
- no goal → no rows at all, no empty heading

**`links.test.ts`**
- `{kind:"goal"}` survives encode → decode

**`index.test.ts`** (wiring, hostless)
- no `goalStoreFile` on the context → no goal rows and the reader is never called
- present → rows on screen after mount
- clicking the goal row opens the viewer with the full objective

### Risks, named

- **Per-refresh file read.** Mitigated by the stat gate; the test that pins "unchanged mtime does
  not re-parse" is what keeps it honest.
- **Internal surface drift.** `goalStoreFile` is documented on the public extension context, but the
  record shape is senpi's own. The reader validates every field and degrades to no section, so a
  shape change costs a missing block, never a crash.
- **Scope creep into goal control.** The panel shows; it does not create, complete or steer goals.
  Anything that writes goal state is out of scope.

## What increment 1 corrected once the writer was read

Two facts the plan assumed from the installed build were wrong against the source, and both were
settled by reading `packages/pi-goal/src/goal/store.ts` rather than a rendered store:

- **Five statuses, not three.** The store writes `active | paused | blocked | budgetLimited |
  complete`. A reader that accepted three dropped the other two as invalid records, so the block
  would disappear exactly when the goal stopped moving. Fixed failing-first; the label for
  `budgetLimited` is the host's own `goalStatusLabel` wording ("limited by budget"), so the column
  and the footer cannot name one state two ways.
- **Two store locations.** `goalStoreRef` answers `<sessionDir>/extensions/goal/<sessionId>.json`
  only once the session has a session file; before the first turn it answers
  `<agentDir>/extensions/goal/no-session/<cwdKey>/<sessionId>.json`. Nothing in the panel depends on
  which one it is - the host hands over the resolved path - but it decides how the section can be
  driven in QA, which is why the evidence records it.
